# ANA-40 — Token health: acceptance criteria → tests

Jira ANA-40, DRS contract `.drs/ANA-40.json` (revision 2, PO decisions (a)–(c) of 2026-10-21). All tests are in
`workers/instagram-oauth/test/worker.test.mjs`, run by `npm run check` and CI `worker-instagram` over the real migration
SQL: the test D1 (`test/d1-sqlite.mjs`) applies every `migrations/*.sql` in file order, including
`0002_token_health.sql`. Meta is mocked and every identifier is synthetic. Test names below are quoted without the
`health: ` prefix. Each test asserts exact values (whole rows, exact health objects, exact call lists, timestamps on a
frozen clock).

| AC | What is checked | Tests |
|---|---|---|
| AC1 | Existing cron `0 5 * * *`, one check per run, at most 1 Meta call: expired → no call; refresh due → only the refresh; only `NOT_DUE` → `/me?fields=user_id`. ## Migration backward compatibility (R2G 4)

`docs/evidence/ANA-40/backcompat-check.sh [BASE] [CANDIDATE]` sets its exit code from three checks, each with a canary:
0001 byte-identical to base; 0002 only plain nullable `ADD COLUMN … INTEGER|TEXT` (canaries: NOT NULL, DEFAULT, CHECK,
UPDATE, TRIGGER, DROP); base `src/` + base `test/worker.test.mjs` pass on the candidate schema (canary: a 0002 that
drops `last_refresh_error` must fail).
