# ANA World (3D) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A `/world` page in ANA LUMEN (rail button "World") that shows Ana, Ben and Vince as character avatars on an
animated, interactive Three.js globe, driven by the dashboard's real measured data (Instagram snapshot, near-real-time
like/comment pulse, Meta audience geography by country/city), released on the Contabo VPS.

**Architecture:** Server-side only data path (browser → `/api/world` → existing access gate → worker / Jira). The worker
gets two additive read-only routes (`/internal/social-pulse`, `/internal/social-audience`) under the existing internal
key. The client is one lazily loaded scene module (Three.js + world-atlas topology) plus a glass HUD built from the
ASADA tokens. Channels are a registry, so a new provider adds a ring without scene changes.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript, three, world-atlas + topojson-client, i18n-iso-countries
(codes only), Vitest, Playwright, Cloudflare Worker (node:test), systemd release on vmi3693936.

## Honesty rules for the scene (binding)

1. Geography arcs = Meta's aggregated audience share by country for the stated timeframe. Never drawn as the origin of
   an individual like or comment. The label says so.
2. "Live" pulses = real deltas of `like_count` / `comments_count` / new media between two pulse reads (≤ 60 s apart
   while the page is open). They burst at the post and at Ana, not at a country.
3. Missing source = visible grey state with the reason (Jira not configured, Vince no source, Confluence later).
4. Ana's place = operator value `WORLD_ANA_PLACE` (region level, server-only, never in Git); absent → "Ort unbekannt".
5. Ambient character animation is decoration and is never presented as activity data.
6. No number in the scene without a provenance tag in the panel.

## Critical review of this plan (before execution)

**Real functionality**
- Risk: Ana's account below 100 engagements in `this_month` → no arcs. Handled as an explicit state; follower
  geography (lifetime threshold 100 followers) is shown as the second layer, so the globe is rarely empty.
- Risk: Jira is not configured on production (observed). The Berlin side would look dead. Decision: show the project
  registry with "Jira nicht verbunden (ANA-33 offen)" and the dashboard's own running release (sha + start time, read
  from the release directory) as the one real Berlin signal. No admin token is used (deploy skill rule).
- Risk: headless WebGL in CI. Chromium ships SwiftShader; the draft rendered headless in this session. Fallback path
  is tested separately, so a missing GPU never hides data.
- Risk: Meta call volume. Pulse = 2 calls per minute only while someone has `/world` open (server cache); audience =
  5 calls per 6 h. Far below platform limits.
- Risk: worker deploy changes production data path. Mitigation: routes are additive; snapshot code untouched; the
  dashboard treats a 404 from the new routes as "not available yet", so release order does not matter.
- Risk: bundle weight. Three.js and the topology load only on `/world` via dynamic import; other pages unchanged.

**Graphic professionalism**
- Continents from real topology (world-atlas 110m) instead of hand-drawn polygons.
- One scene palette module; every mesh uses the same toon ramp and the same ink outline; no ad-hoc colours.
- Characters: big-head proportions (head ≈ 0.45 body height), signature traits modelled as geometry (beard, moustache,
  hair silhouette, sunglasses, gingham texture, tattoo decal), not as labels.
- Camera views composed per scene (oblique close-ups), labels as glass chips that avoid the HUD.

**Stylistic consistency**
- HUD uses the ASADA tokens (glass fill, chrome edge, Inter, coral only as accent, person tints). Sky is the ASADA
  canvas gradient so the 3D stage sits inside the app instead of next to it. Ink colour = `--text`.
- Comic is confined to the 3D stage; typography and panels stay dashboard.
